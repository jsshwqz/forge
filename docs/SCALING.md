## 限制清单 (D2)

### 限制 1: SSE 广播进程内隔离

**现状**: SSE 广播通过进程内 broadcast channel 实现，多副本间事件不通。
**触发信号**: 副本 A 触发的编排事件，副本 B 的 UI 收不到实时更新。
**解法预留**: PG LISTEN/NOTIFY 或 Redis Pub/Sub（第二期实现）。
**严重度**: 中

### 限制 2: UUID 碰撞风险

**现状**: uuid_lite 类时间戳 ID 在多副本同时生成时存在碰撞风险。
**触发信号**: 出现重复 ID 导致数据库唯一约束违反。
**解法预留**: 统一换用 DB 序列或真 UUID v7（需评估迁移成本）。
**严重度**: 高

### 限制 3: 内存 Store 仅限测试

**现状**: InMemory*Store 系列夹具仅用于单元测试和集成测试，生产环境必须使用 Pg*Store。
**触发信号**: 服务重启后数据丢失。
**解法预留**: N/A（架构设计如此）。
**严重度**: 低（已知限制）

---

## 单机边界

当前架构设计目标为单机部署：
- 数据库：单实例 PostgreSQL
- 缓存：无（可引入 Redis 第二期）
- 消息队列：无（SSE 广播为进程内）

**水平扩展前提条件**:
1. 解决 UUID 碰撞（限制 2）
2. 引入分布式事件广播（限制 1）
3. 数据库连接池调优（FORGE_DB_MAX_CONN）
